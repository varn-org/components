# 🗄 vdo

Varn Data Objects — a PDO-style database facade over sqlite, mysql/mariadb, and postgres, implemented in Lua on top of the native `ffi` module. The backend is selected from the DSN scheme, and the same connection, statement, and transaction API works across all three drivers, which are loaded lazily so a client library that is not installed is never forced.

```lua
local vdo = require("vdo")

local db = vdo.connect("sqlite::memory:")

db:exec("CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT NOT NULL)")

local insert = db:prepare("INSERT INTO users (name) VALUES (:name)")
insert:execute({ name = "alice" })
insert:close()

for _, row in ipairs(db:query("SELECT id, name FROM users"):fetchAll()) do
    print(row.id, row.name)
end

db:close()
```

Statements are backed by native handles through `ffi`, so a connection and its cursors must be closed in the same scope that opened them (an unclosed statement is finalized when collected, but explicit `close()` releases the lock immediately). Native-only — it depends on the native `ffi` module and the client library for the chosen driver, unavailable in the browser.

## DSN

The scheme picks the driver: `sqlite:` (or `sqlite3:`) keeps the remainder verbatim as a filesystem path or the `:memory:` token, while `mysql:` / `mariadb:` and `pgsql:` / `postgres:` / `postgresql:` take a `key=value;key=value` body (`host`, `port`, `dbname`, and driver-specific keys).

## Connection

| Function | What it does |
|---|---|
| `vdo.connect(source, username?, password?, options?)` | Parse the DSN in `source`, open the connection through the matching driver, and return it; explicit `username` / `password` override any in the DSN. |
| `db:prepare(sql)` | Compile a statement and return it for binding and reuse. |
| `db:query(sql, params?)` | Prepare, execute once with `params`, and return the executed statement ready to fetch. |
| `db:exec(sql)` | Run a statement (or a multi-statement script on sqlite) directly and return the affected-row count. |
| `db:lastInsertId()` | The id generated by the last insert. |
| `db:beginTransaction()` / `db:commit()` / `db:rollBack()` | Open, commit, or roll back an explicit transaction. |
| `db:inTransaction()` | Whether a transaction is currently open. |
| `db:transaction(fn)` | Run `fn(db)` inside a transaction, committing on success and rolling back then re-raising on any error, returning the value of `fn`. |
| `db:close()` | Close the connection. |

## Statement API

| Function | What it does |
|---|---|
| `stmt:execute(params)` | Bind `params` and run the statement now; returns the statement so calls can chain. |
| `stmt:fetch()` | The next row as a name-keyed table, or `nil` when the result is exhausted. |
| `stmt:fetchAll()` | Every remaining row as a sequence of name-keyed tables. |
| `stmt:rowCount()` | The affected-row count (see the portability note below). |
| `stmt:columnCount()` | The number of columns in the result. |
| `stmt:close()` | Finalize the statement and release its lock. |

Placeholders come in two forms, resolved by `vdo.sql`: positional `?` bound from an array in `params`, and named `:name` bound from a map, while markers inside string literals, comments, and postgres `::` casts are left untouched.

## rowCount is not portable across drivers for a SELECT

For an insert, update, or delete `rowCount()` returns the number of rows changed on every driver. For a **SELECT** it is not portable: on sqlite it returns the last DML change count (mirroring PDO's sqlite behaviour), while pgsql and mysql return the selected-row total. Use `#stmt:fetchAll()` for a portable count of selected rows.
